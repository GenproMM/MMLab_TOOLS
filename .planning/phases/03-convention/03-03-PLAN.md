| MM012 | warning | `from pyrevit import forms`, `from pyrevit.forms import …` или `import pyrevit.forms` → «pyrevit.forms не работает под CPython3; используй TaskDialog/WinForms» |
| MM014 | warning | неканонический lib-бутстрап (D-06, D-15). Триггеры (любой): (а) использование имени `EXTENSION_ROOT` (ast.Name в любом контексте); (б) вызов `<expr>.join(...)` (ast.Attribute attr=="join") с 4+ аргументами-константами `".."` — подъём в корень репо; (в) вызов `sys.path.insert/append/extend` (цепочка ast.Attribute: Name "sys" → attr "path" → метод), не равный канону `sys.path.insert(0, _LIB_DIR)` (args[0] — Constant 0, args[1] — Name "_LIB_DIR"). Сообщение отсылает к каноническому блоку `_EXTENSION_DIR`/`_LIB_DIR` (шаблон / AGENTS.md) |

ALLOWED_ROOTS (строится функцией `allowed_import_roots(root)`):

- хост-платформа: {"clr", "System", "Autodesk", "pyrevit", "Microsoft"}
- first-party: стемы файлов `<root>/MM LAB.extension/lib/*.py` (динамически; сейчас ios_common_helpers, revit_ui_helpers, revit_compat)
- vendored: {"openpyxl", "et_xmlfile"}

Применение: check_script и check_pushbutton прогоняют AST-правила на script.py; MM010–MM012 и MM014 не фильтруются baseline'ом иначе, чем прочие (обычная механика (path, code)).

Канонический бутстрап (единственная форма, НЕ дающая MM014; дословно D-15 — эталон для теста чистого случая):

```python
import os
import sys

_SCRIPT_DIR = os.path.dirname(__file__)
# pushbutton -> panel -> tab -> MM LAB.extension
_EXTENSION_DIR = os.path.normpath(os.path.join(_SCRIPT_DIR, "..", "..", ".."))
_LIB_DIR = os.path.join(_EXTENSION_DIR, "lib")
if os.path.isdir(_LIB_DIR) and _LIB_DIR not in sys.path:
    sys.path.insert(0, _LIB_DIR)
```
