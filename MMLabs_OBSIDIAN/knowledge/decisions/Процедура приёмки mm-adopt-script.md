# Процедура приёмки сторонних скриптов — `/mm-adopt-script`

## Решение
Конвенция MM LAB предусматривает процедуру полуавтоматической приёмки сторонних pyRevit-скриптов в MM LAB.tab с гарантированной адаптацией под конвенцию и машинной проверкой на каждом этапе.

## Почему
1. **Переиспользование кода**: кнопки часто берутся из внешних источников (примеры, легаси, чужие репозитории), но зачастую не соответствуют внутренним стандартам.
2. **Качество и надёжность**: машинный чекер конвенции (`tools/check_convention.py --strict`) гарантирует, что в репозиторий попадают только кнопки с чистым кодом.
3. **Разделение ответственности**: процедура содержит явные гейты (шаг 7 РЕВЬЮ-ГЕЙТ) — человек принимает решение, агент исполняет.

## Как это работает
Каноническая процедура в `agents/commands/mm-adopt-script.md` состоит из 11 шагов:

1. **Вход**: путь к стороннему `.py`-скрипту или папке.
2. **Исходный отчёт чекера** (raw mode `--json`): список нарушений MM000–MM014 — опорная точка для рассказа об адаптации.
3. **Панель (D-10)**: эвристическая подсказка по содержимому скрипта (OST_Windows → АРХИТЕКТУРА, OST_Duct → ИОС и т.д.), согласование с пользователем.
4. **Имя кнопки**: из `__title__` исходника или имени файла, согласование.
5. **Адаптация (D-08/D-11)**: 
   - Переполнение в `script.py` по конвенции (шапка MM001–MM004, явные импорты MM009, revit_compat вместо LookupParameter MM010, except Exception MM011, lib-бутстрап MM014, fail-fast версии D-03, транзакционный каркас, doc/uidoc параметрами).
   - Создание `bundle.yaml` (title/tooltip ru+en).
   - Создание `README.md` (описание, логика, параметры, совместимость).
   - Копирование иконки как `icon.png`.
6. **Гейт-проверка**: `--strict` до exit 0 — исправляй, повторяй.
7. **РЕВЬЮ-ГЕЙТ (D-08)** — блокирующий: показ сводки правок (с MM-кодами) и полного diff'а; ждём явного «да» / «одобряю». Без одобрения — стоп, ничего не регистрируем.
8. **Регистрация (D-11)** — только после одобрения: запись в `layout:` панели, удаление из baseline `pending_adoption` (если была), общий прогон чекера.
9. **Quick task GSD**: `/gsd-quick` (или ручное создание `.planning/quick/` артефактов для Gemini/Kilo).
10. **Коммит (D-17)**: пофайловый стейджинг (кнопка + panel bundle + baseline + quick task).
11. **Финал**: напоминание о pyRevit Reload и UAT в живом Revit.

## Ключевые гейты
- **Не исполнять сторонний код** (правило безопасности).
- **D-08 РЕВЬЮ-ГЕЙТ** — человек решает, агент исполняет.
- **D-17 пофайловый стейджинг** — `git add .` запрещён.
- **D-18 push только после подтверждения**.

## Пример: IFC_Окна (2026-07-24)
Скрипт из внешнего источника (не было в MM LAB.tab). Анализ:
- Содержимое: `OST_Windows`, заполнение GP_01_* параметров → панель **АРХИТЕКТУРА**.
- Нарушения: 16 (MM001, MM002, MM004, MM009, MM010/11/12, 7× голые `except:`).
- Аналог: `IFC_Двери` — тот же паттерн (WinForms multiselect, revit_compat, `revit_ui_helpers`).
- Адаптация: ~10 минут (замены на конвенцию, создание YAML/README, иконка).
- РЕВЬЮ-ГЕЙТ: одобрено.
- Регистрация: добавлена в layout, снята из pending (было в baseline).
- Результат: коммит c85e0f8, quick task 260724-win, чекер exit 0.
