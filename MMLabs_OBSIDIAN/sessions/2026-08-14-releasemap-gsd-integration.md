# Сессия 2026-08-14: `/mm-releasemap-download` и интеграция с GSD

## Что сделано

Завершена новая команда `/mm-releasemap-download` с полной переопределением семантики — теперь команда явно связывает **Карту релизов** и **GSD**:
- Версия релиза vYYMMDD → фаза GSD `Phase vYYMMDD`
- ID задания → требование GSD `REQ-<ID>`
- Дата фазы — только из версии релиза (колонка «План релиза» — рудимент, удалена)
- Статус «Релиз» в CSV подтверждает закрытие требования в GSD ([x])
- Фаза закрыта, когда закрыты **все** её требования

### Ключевые компоненты

**`gsd_release_sync.py`:**
- Новая подкоманда `fetch`: забирает свежий CSV из `%USERPROFILE%\Downloads`
- Функции `req_id()`, `phase_name()`, `release_date()`, `phase_status()` для соответствия GSD
- Чекпоинт: гейт «новое требование заводится только со статусом Не начато» (защита от работы мимо GSD)
- Подкоманда `reset`: зачистка `.planning/` под новый набор заданий, фазы GSD переживают смену
- Блок `ЗАКРЫТО:` в отчёте синка: какие требования закрыл новый CSV, какие фазы закрылись

**Документация:**
- `agents/commands/mm-releasemap-download.md` — полная процедура с шагом о reset
- `RELEASE_MAP/README.md` — таблица соответствия Карта ↔ GSD, правила статусов фаз, гейты
- `CLAUDE.md` / `AGENTS.md` — секции про reset и GSD-соответствие

**Тестирование:**
- 100 тестов (было 95 + 5 на reset); 39 тестов на sync-docs/reset, 12 на fetch
- Проверены: обновление всех полей из CSV, откат статуса, гейт новых заданий, статус фаз, выживание ручных `## Phase N`, идемпотентность reset

## Ключевые решения

1. **Даты фаз из версии релиза, не из CSV**: версия vYYMMDD — единственный источник даты; колонка «План релиза» удалена полностью.
2. **Гейт новых требований**: «Не начато» в статусе обязателен при первом появлении требования в GSD (защита от работы в обход системы).
3. **Пространства имён не пересекаются**: `Phase vYYMMDD`/`REQ-<ID>` (Карта релизов) vs `Phase N: <название>`/собственные коды (GSD), поэтому новый набор не требует закрытия milestone.
4. **Reset не трогает текущие фазы GSD**: заметки, decisions, debugging, phases/ переживают смену набора; только генерируемые блоки обнуляются.
