# Полный цикл разработки кнопки MM LAB — методичка демонстрации

Показательный прогон для новичков в кодинге и работе с ИИ: как задание из Карты релизов
превращается в рабочую кнопку pyRevit и возвращается в план уже закрытым требованием.

- **Демо-задание:** `REQ-2010001` (фаза `v260814`, приоритет MVP) — «Создать кнопку
  которая будет проверять рабочий набор осей и переназначать на рабочий набор
  "00_Уровни и оси"».
- **Результат:** кнопка `Рабочий набор осей` на панели **КООРДИНАЦИЯ**, прошедшая
  строгий гейт конвенции и проверенная в живом Revit; требование `REQ-2010001` в
  статусе «Релиз».
- **Длительность:** ориентир 15 минут (7 шагов).
- **Главная мысль для зрителя:** разработчик не пишет код руками и не запускает скрипты —
  он ставит задачу словами, а качество держат машинные гейты (чекер конвенции) и
  проверка в Revit.

## Карта демонстрации

| # | Шаг | Что копируем в Claude Code | Что видит зритель |
|---|-----|----------------------------|-------------------|
| 1 | Обновить задания и взять REQ в работу | `Синхронизируй gsd, затем возьми REQ-2010001 в работу` | `ROADMAP.md`: требование приехало из Google-таблицы и стало «В работе» |
| 2 | Скаффолд кнопки из шаблона | `/mm-new-button РабочийНаборОсей КООРДИНАЦИЯ` | новая папка кнопки из 3 файлов + запись в `layout:` панели |
| 3 | Реализовать логику | `Реализуй REQ-2010001 в кнопке РабочийНаборОсей. README кнопки обнови под фактическую логику.` | агент сам находит требование и пишет код |
| 4 | Машинный гейт конвенции | `/mm-check "MM_LAB.extension/MM Lab.tab/КООРДИНАЦИЯ.panel/РабочийНаборОсей.pushbutton" --strict` | `ошибок: 0` — код соответствует стандарту |
| 5 | Тест в Revit (UAT) | pyRevit Reload → нажать кнопку | оси реально переехали на `00_Уровни и оси` |
| 6 | Закрыть требование | `REQ-2010001 проверено в Revit — переведи его в «Релиз» и обнови плановые документы` | в `ROADMAP.md` появилась отметка `[x]` |
| 7 | Сохранить сессию | `сохрани сессию` | один коммит с понятным описанием + заметка в Obsidian |

Ни один шаг демонстрации не требует ручного запуска python — все команды скрипта
Карты релизов выполняет агент. Точные команды на случай сбоя — в
[Приложении А](#приложение-а--шпаргалка-ведущего).

## 1. Подготовка (до демонстрации, зрителям не показывается)

### 1.1. Привести репозиторий в стартовое состояние

Стартовая точка обоих прогонов — чистый `master`. Если в рабочем дереве остались
незакоммиченные изменения `.planning/*` или CSV Карты релизов, зафиксируй их отдельным
коммитом ДО начала:

```bash
git -c core.quotepath=false status --porcelain
```

Пустой вывод = можно начинать.

### 1.2. Завести ветку прогона

Весь прогон живёт в отдельной ветке — так его целиком снимает одна команда отката.

```bash
# репетиция
git switch -c demo-rehearsal

# демонстрация (после отката репетиции)
git switch -c demo-live
```

### 1.3. Выгрузить свежую Карту релизов

Скачай браузером лист **«Скрипты_Карта релизов»** из Google-таблицы «Сводный Реестр
Плагинов» в формате CSV. Файл должен лежать в `%USERPROFILE%\Downloads` — перекладывать
его никуда не нужно, шаг `fetch` заберёт его сам и **не удалит** оригинал. Поэтому один
и тот же скачанный файл переиспользуется и на репетиции, и на демонстрации.

Проверь в Google-таблице, что у задания `2010001` статус **«Не начато»** — иначе
шаг 1 не покажет перехода в работу.

### 1.4. Подготовить Revit

- Revit 2020, 2022 или 2024 (другие версии кнопка отсечёт по гейту версии);
- открыта **общая (workshared) модель** — без worksharing рабочих наборов нет;
- в модели **есть рабочий набор `00_Уровни и оси`** — кнопка его не создаёт, только ищет;
- в модели **есть оси, лежащие на других рабочих наборах** — иначе переносить будет нечего
  и зритель не увидит эффекта;
- pyRevit установлен, расширение `MM_LAB.extension` подключено, вкладка **MM Lab** видна.

### 1.5. Pre-flight чек-лист

- [ ] `git status --porcelain` пустой, создана ветка прогона
- [ ] свежий CSV листа «Скрипты_Карта релизов» лежит в «Загрузках»
- [ ] `REQ-2010001` в Google-таблице в статусе «Не начато»
- [ ] Revit открыт на общей модели с рабочим набором `00_Уровни и оси`
- [ ] в модели есть оси на «неправильных» рабочих наборах
- [ ] вкладка MM Lab видна в Revit
- [ ] открыт Claude Code в каталоге репозитория
- [ ] методичка открыта на этом разделе — дальше только копирование блоков

## 2. Шаги демонстрации

### Шаг 1. Обновить задания из Карты релизов и взять требование в работу

**Цель:** показать, что план разработки не придумывается в чате — он приезжает из
Google-таблицы, которую ведут менеджеры и BIM-координаторы.

Копируем в Claude Code:

```text
Синхронизируй gsd, затем возьми REQ-2010001 в работу
```

**Что произойдёт.** Агент выполнит процедуру `/mm-releasemap-download`: заберёт CSV из
«Загрузок», проверит структуру листа, перегенерирует `.planning/ROADMAP.md`,
`REQUIREMENTS.md`, `PROJECT.md` и `release-map.json`. Затем переведёт задание `2010001`
в статус «В работе» и повторит генерацию документов.

**Что показать зрителю.** Открой [.planning/ROADMAP.md](../.planning/ROADMAP.md), фаза
`Phase v260814`. Строка требования должна выглядеть так:

```text
- [ ] **REQ-2010001** — Рабочий набор (ФУНКЦИОНАЛ, MVP) — Создать кнопку которая будет
  проверять рабочий набор осей и переназначать на рабочий набор "00_Уровни и оси" — _В работе_
```

**Что проговорить.** Единственный источник правды — Google-таблица. Правки в
`.planning/*.md` руками бессмысленны: следующая синхронизация их перезапишет. Смена
статуса командой живёт в локальной копии CSV до следующей выгрузки — в реальной работе
статус надо продублировать в таблице.

---

### Шаг 2. Создать кнопку из шаблона

**Цель:** показать, что структура кнопки не сочиняется каждый раз — она копируется из
канонического шаблона репозитория.

Копируем:

```text
/mm-new-button РабочийНаборОсей КООРДИНАЦИЯ
```

**Что произойдёт.** Агент скопирует `templates/НоваяКнопка.pushbutton` в
`MM_LAB.extension/MM Lab.tab/КООРДИНАЦИЯ.panel/РабочийНаборОсей.pushbutton`, заполнит
метки `TODO` (название, подпись, подсказка, README) и допишет запись
`- РабочийНаборОсей` в `layout:` файла `КООРДИНАЦИЯ.panel/bundle.yaml`. Название и панель
он может переспросить — подтверди.

**Что показать зрителю.** Новую папку из трёх файлов и строку в `layout:` панели.

**Что проговорить.** Кнопка, не указанная в `layout:`, на панели просто не появится —
это самая частая ошибка новичка, и поэтому регистрация автоматизирована. Панель
КООРДИНАЦИЯ выбрана потому, что оси и уровни — общая координационная основа модели,
рядом уже живёт кнопка «Переименовать уровни».

---

### Шаг 3. Реализовать логику кнопки

**Цель:** главный момент демонстрации — постановка задачи словами, без единой строки
кода от человека.

Копируем:

```text
Реализуй REQ-2010001 в кнопке РабочийНаборОсей. README кнопки обнови под фактическую логику.
```

**Что произойдёт.** Агент найдёт текст требования в плановых документах, сверится
со стандартом `AGENTS.md` и напишет логику: проверка, что модель общая → поиск рабочего
набора `00_Уровни и оси` → сбор всех осей → чтение текущего рабочего набора → перенос
в одной транзакции → итоговый отчёт в диалоге.

Ни путь к требованию, ни путь к стандарту в промпте не указаны намеренно: `AGENTS.md`
подключён к каждой сессии строкой `@AGENTS.md` в корневом `CLAUDE.md`, а требование
`REQ-2010001` агент находит по идентификатору. Если он всё же начал искать вслепую —
подскажи одной фразой: `Требование REQ-2010001 — в .planning/ROADMAP.md`.

**Что показать зрителю.** Дифф `script.py`: коротко пройтись по структуре — шапка
с версиями Revit, подключение библиотеки, `main()`, транзакция.

**Что проговорить.** Промпт намеренно короткий: подробная постановка уже написана в
требовании `REQ-2010001`, а правила написания кода — в `AGENTS.md`. Пересказывать их
в чате не нужно — достаточно назвать номер требования. Если что-то в требовании
сформулировано неточно, это видно сразу — и правится в Карте релизов, а не в чате.

> Если результат заметно расходится с ожидаемым — не спорь с агентом на глазах у зала:
> вставь эталон из [Приложения Б](#приложение-б--эталонный-scriptpy) и продолжай.

---

### Шаг 4. Прогнать машинный гейт конвенции

**Цель:** показать, что качество кода проверяет не человек на глаз, а программа.

Копируем:

```text
/mm-check "MM_LAB.extension/MM Lab.tab/КООРДИНАЦИЯ.panel/РабочийНаборОсей.pushbutton" --strict
```

**Что произойдёт.** Запустится `tools/check_convention.py` в режиме приёмки: проверит
шапку файла, кодировку, наличие `README.md` и `bundle.yaml`, регистрацию в `layout:`,
список импортов, запрет `LookupParameter` со строковым именем, канонический бутстрап
библиотеки и отсутствие мусора в папке. Ожидаемый результат:

```text
Проверено: 1, ошибок: 0, предупреждений: 0
```

**Если гейт красный** — скажи агенту:

```text
Исправь нарушения, которые нашёл чекер, и прогони /mm-check ещё раз. Канонический lib-бутстрап и каркас транзакции не переписывай.
```

**Что проговорить.** `--strict` — гейт приёмки: он игнорирует «замороженные» послабления
для старых кнопок и считает ошибкой даже предупреждения. Новая кнопка обязана пройти его
до нуля. Это и есть замена ручному код-ревью на первом уровне.

---

### Шаг 5. Проверить кнопку в Revit (UAT)

**Цель:** показать, что зелёный чекер — не доказательство работоспособности. Настоящая
приёмка только в живой модели.

Действия (без копирования, руками в Revit):

1. вкладка **pyRevit** → **Reload** (или перезапустить Revit) — расширение читается при старте;
2. вкладка **MM Lab** → панель **КООРДИНАЦИЯ** → кнопка **Рабочий набор осей**;
3. прочитать вслух итоговый диалог.

**Чек-лист приёмки:**

- [ ] кнопка появилась на панели КООРДИНАЦИЯ и запускается без ошибок;
- [ ] в диалоге показано общее число осей, сколько перенесено, сколько уже было
      на целевом наборе, сколько не удалось;
- [ ] в свойствах любой оси рабочий набор стал `00_Уровни и оси`
      (проверить в Диспетчере рабочих наборов или в свойствах элемента);
- [ ] повторное нажатие кнопки сообщает, что переносить больше нечего
      (все оси уже на целевом наборе) — операция идемпотентна.

**Что проговорить.** Все изменения модели идут внутри одной транзакции: либо применились
все, либо ни одно. Отменить результат можно обычным Ctrl+Z. Оси, занятые другим
пользователем, кнопка не ломает — она их считает в «не удалось» и сообщает об этом.

---

### Шаг 6. Закрыть требование

**Цель:** замкнуть цикл — работа возвращается в тот же план, из которого началась.

Копируем:

```text
REQ-2010001 проверено в Revit — переведи его в «Релиз» и обнови плановые документы
```

**Что произойдёт.** Агент проведёт статус по жизненному циклу
(«В работе» → «Готово» → «Релиз») и перегенерирует плановые документы. В выводе появится
блок `ЗАКРЫТО:` с перечнем закрытых требований.

**Что показать зрителю.** Строку требования в `ROADMAP.md` — теперь с отметкой `[x]`
и статусом «Релиз»:

```text
- [x] **REQ-2010001** — Рабочий набор (ФУНКЦИОНАЛ, MVP) — … — _Релиз_
```

**Что проговорить.** Закрытием считается только статус «Релиз»; «Готово» — это код
написан, но пользователю ещё не отдан. Фаза `v260814` при этом останется в работе:
в ней три требования, закрыли одно. Так и должно быть — фаза закрывается, когда закрыты
все её требования.

---

### Шаг 7. Сохранить сессию

**Цель:** показать, что история изменений и знания о проекте сохраняются автоматически.

Копируем:

```text
сохрани сессию
```

**Что произойдёт.** Агент создаст заметку сессии в `MMLabs_OBSIDIAN/sessions/`, обновит
текущие приоритеты, добавит в коммит только файлы этой сессии (пофайлово, явными путями)
и сделает коммит по обязательному шаблону. Push сделает только после отдельного
подтверждения — на демонстрации его не делаем.

**Что показать зрителю.** `git log -1` — сообщение коммита с разделами «Сессия»,
«Изменённые файлы», «Результаты».

**Итог демонстрации.** Задание из Google-таблицы → рабочая кнопка в Revit → закрытое
требование → коммит с историей. Человек написал 7 фраз.

## 3. Откат прогона

После репетиции (и после демонстрации, если нужно повторить) прогон снимается целиком:

```bash
git switch master
git branch -D demo-rehearsal
git clean -fd "MM_LAB.extension/MM Lab.tab/КООРДИНАЦИЯ.panel/РабочийНаборОсей.pushbutton"
rm -f RELEASE_MAP/status-journal.csv
```

Пояснения:

- `git branch -D` снимает всё, что было закоммичено на шаге 7;
- `git clean -fd` нужен, если шаг 7 не выполнялся: файлы кнопки остались бы
  неотслеживаемыми и переехали бы в следующий прогон;
- `RELEASE_MAP/status-journal.csv` — журнал переходов статусов, он в `.gitignore`
  и веткой не откатывается; удаляем, чтобы демонстрация началась с чистого журнала;
- ветку `demo-live` откатывают той же командой, подставив её имя.

Проверка перед следующим прогоном:

```bash
git -c core.quotepath=false status --porcelain
```

Вывод должен быть пустым, а папки
`MM_LAB.extension/MM Lab.tab/КООРДИНАЦИЯ.panel/РабочийНаборОсей.pushbutton` не должно
существовать. В Revit после отката сделай pyRevit Reload — иначе кнопка останется
на панели от прошлого прогона.

Модель Revit откатывается отдельно: закрой её **без синхронизации** (или отмени перенос
через Ctrl+Z), чтобы оси вернулись на исходные рабочие наборы.

## Приложение А — шпаргалка ведущего

Точные команды на случай, если агент не сработал или нужно быстро поправить состояние.
Запускать из корня репозитория.

**Карта релизов:**

```bash
python3 RELEASE_MAP/gsd_release_sync.py fetch        # забрать CSV из «Загрузок»
python3 RELEASE_MAP/gsd_release_sync.py check        # валидация листа
python3 RELEASE_MAP/gsd_release_sync.py sync-docs    # перегенерировать .planning/*
python3 RELEASE_MAP/gsd_release_sync.py sync         # fetch + check + sync-docs
```

**Статусы демо-задания:**

```bash
python3 RELEASE_MAP/gsd_release_sync.py status 2010001 "В работе"
python3 RELEASE_MAP/gsd_release_sync.py status 2010001 "Готово"
python3 RELEASE_MAP/gsd_release_sync.py status 2010001 "Релиз"
python3 RELEASE_MAP/gsd_release_sync.py sync-docs
```

Допустимые статусы и порядок: `Не начато → В работе → Готово → Релиз`. Откат статуса
назад разрешён, скрипт печатает предупреждение.

**Чекер конвенции:**

```bash
py -3 tools/check_convention.py "MM_LAB.extension/MM Lab.tab/КООРДИНАЦИЯ.panel/РабочийНаборОсей.pushbutton" --strict
py -3 tools/check_convention.py --all --baseline tools/convention_baseline.json
```

Exit-коды: `0` — чисто, `1` — нарушения, `2` — ошибка вызова.

## Приложение Б — эталонный `script.py`

Прошёл `py -3 tools/check_convention.py … --strict` с результатом
`ошибок: 0, предупреждений: 0`. Используй, если на демонстрации агент выдал нерабочий
вариант: замени содержимое
`MM_LAB.extension/MM Lab.tab/КООРДИНАЦИЯ.panel/РабочийНаборОсей.pushbutton/script.py`
и продолжай с шага 4.

### Постановка логики (развёрнуто)

1. гейт версии Revit — `revit_compat.require_supported_version(...)` первой строкой `main()`;
2. модель открыта и является общей (`doc.IsWorkshared`), иначе — сообщение и выход;
3. поиск пользовательского рабочего набора `00_Уровни и оси`
   (`FilteredWorksetCollector` + `WorksetKind.UserWorkset`); нет набора — сообщение и выход;
4. сбор всех осей (`BuiltInCategory.OST_Grids`, `WhereElementIsNotElementType`);
5. текущий рабочий набор оси — через `revit_compat.get_parameter(...)`
   с `BuiltInParameter.ELEM_PARTITION_PARAM`; оси, уже лежащие на целевом наборе, пропускаются;
6. перенос всех остальных — внутри одной транзакции;
7. итог в `TaskDialog`: всего / перенесено / пропущено / не удалось, с ID осей.

### Код

```python
#! python3
# -*- coding: utf-8 -*-
"""Рабочий набор осей

Проверяет рабочий набор у осей проекта и переназначает их
на рабочий набор "00_Уровни и оси".

Совместимость: Revit 2020 / 2022 / 2024
Зависимости: нет
"""

__title__ = "Рабочий набор\nосей"
__author__ = "GENPRO LAB"

import os
import sys

_SCRIPT_DIR = os.path.dirname(__file__)
# pushbutton -> panel -> tab -> MM_LAB.extension
_EXTENSION_DIR = os.path.normpath(os.path.join(_SCRIPT_DIR, "..", "..", ".."))
_LIB_DIR = os.path.join(_EXTENSION_DIR, "lib")
if os.path.isdir(_LIB_DIR) and _LIB_DIR not in sys.path:
    sys.path.insert(0, _LIB_DIR)

import clr

clr.AddReference("RevitAPI")
clr.AddReference("RevitAPIUI")

from Autodesk.Revit.DB import BuiltInCategory
from Autodesk.Revit.DB import BuiltInParameter
from Autodesk.Revit.DB import FilteredElementCollector
from Autodesk.Revit.DB import FilteredWorksetCollector
from Autodesk.Revit.DB import Transaction
from Autodesk.Revit.DB import WorksetKind
from Autodesk.Revit.UI import TaskDialog

import revit_compat


COMMAND_NAME = u"Рабочий набор осей"
TARGET_WORKSET_NAME = u"00_Уровни и оси"


def find_workset(doc, workset_name):
    """Ищет пользовательский рабочий набор по имени. Возвращает Workset или None."""
    worksets = FilteredWorksetCollector(doc).OfKind(WorksetKind.UserWorkset)
    for workset in worksets:
        if workset.Name == workset_name:
            return workset
    return None


def collect_grids(doc):
    """Возвращает все экземпляры осей проекта."""
    return (
        FilteredElementCollector(doc)
        .OfCategory(BuiltInCategory.OST_Grids)
        .WhereElementIsNotElementType()
        .ToElements()
    )


def reassign_grids(doc, grids, target_workset_id):
    """Переназначает оси на целевой рабочий набор.

    Транзакцию открывает вызывающий код. Возвращает кортеж
    (перенесено, уже в наборе, не удалось) — списки ID осей.
    """
    moved = []
    skipped = []
    failed = []
    for grid in grids:
        grid_id = revit_compat.element_id_value(grid.Id)
        parameter = revit_compat.get_parameter(
            grid, BuiltInParameter.ELEM_PARTITION_PARAM
        )
        if parameter is None or parameter.IsReadOnly:
            failed.append(grid_id)
            continue
        if parameter.AsInteger() == target_workset_id:
            skipped.append(grid_id)
            continue
        try:
            parameter.Set(target_workset_id)
            moved.append(grid_id)
        except Exception:
            failed.append(grid_id)
    return moved, skipped, failed


def format_report(total, moved, skipped, failed):
    """Собирает текст итогового отчёта для TaskDialog."""
    lines = [
        u"Всего осей в проекте: {0}".format(total),
        u"Перенесено на «{0}»: {1}".format(TARGET_WORKSET_NAME, len(moved)),
        u"Уже были на целевом наборе: {0}".format(len(skipped)),
        u"Не удалось изменить: {0}".format(len(failed)),
    ]
    if moved:
        lines.append(u"")
        lines.append(u"ID перенесённых осей: {0}".format(
            u", ".join(str(grid_id) for grid_id in moved)
        ))
    if failed:
        lines.append(u"")
        lines.append(u"ID проблемных осей: {0}".format(
            u", ".join(str(grid_id) for grid_id in failed)
        ))
        lines.append(u"Вероятная причина: элемент занят другим пользователем.")
    return u"\n".join(lines)


def main():
    """Точка входа кнопки: проверка осей и перенос на целевой рабочий набор."""
    revit_compat.require_supported_version(COMMAND_NAME)

    uidoc = __revit__.ActiveUIDocument
    if uidoc is None or uidoc.Document is None:
        TaskDialog.Show(COMMAND_NAME, u"Открой проект Revit и повтори команду.")
        return
    doc = uidoc.Document

    if not doc.IsWorkshared:
        TaskDialog.Show(
            COMMAND_NAME,
            u"Модель не является общей (worksharing выключен).\n"
            u"Рабочих наборов в ней нет — переназначать нечего.",
        )
        return

    target_workset = find_workset(doc, TARGET_WORKSET_NAME)
    if target_workset is None:
        TaskDialog.Show(
            COMMAND_NAME,
            u"В модели нет рабочего набора «{0}».\n"
            u"Создай его и повтори команду.".format(TARGET_WORKSET_NAME),
        )
        return
    target_workset_id = target_workset.Id.IntegerValue

    grids = collect_grids(doc)
    total = revit_compat.iter_count(grids)
    if total == 0:
        TaskDialog.Show(COMMAND_NAME, u"В проекте нет осей.")
        return

    transaction = Transaction(doc, COMMAND_NAME)
    transaction.Start()
    try:
        moved, skipped, failed = reassign_grids(doc, grids, target_workset_id)
        transaction.Commit()
    except Exception:
        transaction.RollBack()
        raise

    TaskDialog.Show(COMMAND_NAME, format_report(total, moved, skipped, failed))


try:
    main()
except SystemExit:
    pass  # require_supported_version уже показал свой диалог
except Exception as ex:
    TaskDialog.Show(COMMAND_NAME, u"Ошибка:\n{0}".format(ex))
```

| Симптом | Причина | Что сделать |

| `/mm-check` красный | агент отступил от стандарта | сказать: «Исправь нарушения, которые нашёл чекер, и прогони `/mm-check` ещё раз. Канонический lib-бутстрап и каркас транзакции не переписывай» |
| Кнопки нет на панели | не сделан pyRevit Reload или нет записи в `layout:` | Reload; проверить `КООРДИНАЦИЯ.panel/bundle.yaml` (правило MM007) |
| «Модель не является общей» | открыта не workshared модель | открыть общую модель либо показать это как корректную обработку негативного сценария |
| «В модели нет рабочего набора …» | в модели нет `00_Уровни и оси` | создать рабочий набор в модели; кнопка его намеренно не создаёт |
| `fetch` печатает `ВНИМАНИЕ` | в «Загрузках» нет выгрузки листа | синк пройдёт по текущему CSV репозитория — для демо приемлемо; для чистого прогона скачать лист заново |
| `check` завершился с ошибкой | сломана структура листа | ошибки правятся в Google-таблице, затем повторная выгрузка CSV; локально CSV не редактируем |
| Требование не появилось в плане | статус в таблице не «Не начато» или пустое «Название плагина» | задание уйдёт в секцию «Не синхронизировано» в `ROADMAP.md` — дозаполнить строку в таблице |
| Кнопка отработала, но диалог пуст | нет осей в проекте | добавить оси в модель |

## Приложение Г — что дальше (в демонстрацию не входит)

Та же кнопка развивается следующими требованиями той же фазы `v260814` — это удобный
ответ на вопрос зрителя «а если задача больше одного шага»:

- **`REQ-2010002`** — отчёт о переназначенных осях с их ID и исходными рабочими наборами,
  с сохранением в `.txt` на локальный диск;
- **`REQ-2010003`** — аналогичная проверка рабочих наборов для уровней (`OST_Levels`).

Цикл для них тот же: взять требование в работу → доработать кнопку → `/mm-check --strict`
→ проверить в Revit → перевести в «Релиз» → сохранить сессию. Когда все три требования
получат статус «Релиз», фаза `v260814` закроется целиком.
