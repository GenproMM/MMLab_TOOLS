Скачать актуальную Карту релизов в planning-документы репозитория. «Скачать» =
взять свежий CSV-экспорт листа «Карта релизов» и перегенерировать из него
`.planning/*`. За один проход, без уточняющих вопросов (правило CLAUDE.md
«### Триггер resync planning docs / Синхронизируй gsd»).

Предпосылка: перед запуском пользователь должен выгрузить свежий экспорт листа
«Карта релизов» в `RELEASE_MAP/Сводный Реестр Плагинов - Карта релизов.csv`
(источник правды). Если экспорт не обновляли — предупреди, что синк пройдёт по
текущему CSV.

1. `python3 RELEASE_MAP/gsd_release_sync.py check` — валидировать структуру
   исходного CSV. Если есть проблемы кроме известных дублей-строк в старых
   релизах — сообщи и остановись.
2. `python3 RELEASE_MAP/gsd_release_sync.py sync-docs` — перегенерировать
   `.planning/release-map.json`, `.planning/ROADMAP.md`,
   `.planning/REQUIREMENTS.md` и блок `Active` в `.planning/PROJECT.md` из живых
   данных CSV. Заполненные `Plans`, строки `Progress` и отметки `[x]` скрипт
   сохраняет сам — вручную их не редактируй.
3. При необходимости обнови `.planning/STATE.md` (скрипт его не трогает: это
   файл состояния GSD — текущая фаза, прогресс, decisions log).
4. Покажи краткий результат (что изменилось) и предложи коммит
   `docs: sync roadmap with release map`.

## `--all` — связать выполненные задачи с сессиями разработки

`ROADMAP.md` / `REQUIREMENTS.md` содержат только backlog со статусом `Не начато`.
Задачи, над которыми уже шла работа (`В работе` / `Готово` / `Релиз`), туда не
попадают. Флаг `--all` дополнительно генерирует `.planning/IMPLEMENTED.md`:
список этих задач (версии `v260605`+), сгруппированный по релизу, где каждая
задача связана с заметками из `MM_CS_Obsidian/sessions/`, упоминающими её ID
(`REQ-<ID>` или голый `<ID>` по границе цифр).

Запуск (вместо шага 2, либо дополнительно к нему):

`python3 RELEASE_MAP/gsd_release_sync.py sync-docs --all`

Помимо обычных документов пишет `.planning/IMPLEMENTED.md` и добавляет ключ
`implemented` в `release-map.json`. Backlog `Не начато` при этом не меняется.
Задачи без найденной сессии помечаются `_(связанная сессия не найдена)_` —
это честный сигнал, что фактическая работа в заметках по ID не зафиксирована.

НЕ редактируй исходник `RELEASE_MAP/Сводный Реестр Плагинов - Карта релизов.csv`.
Изменение статусов задач — отдельная команда [`/mm-releasemap-update`](mm-releasemap-update.md);
выгрузка правок обратно в Google-таблицу — [`/mm-releasemap-upload`](mm-releasemap-upload.md).
