# /mm-save-session — сессионный коммит по шаблону + заметки Obsidian

Завершение рабочей сессии (D-16, D-21): захват знаний в Obsidian-хранилище
`./MMLabs_OBSIDIAN`, затем один коммит ТОЛЬКО из файлов текущей сессии
по обязательному шаблону из `AGENTS.md` §Git-регламент. Push — отдельно,
только с подтверждения (D-18). Фраза пользователя «сохрани сессию» = эта команда.

## Аргументы

Нет обязательных. Опционально — краткая тема сессии для заголовка коммита
и имени заметки; если не передана — сформулируй по фактической работе
и согласуй с пользователем.

## Процедура

1. **Определи файлы ТЕКУЩЕЙ сессии** — только созданные/изменённые самим агентом
   в этой сессии (веди список по ходу работы). Сверь с фактическим состоянием:

   ```bash
   git -c core.quotepath=false status --porcelain
   ```

   ЧУЖИЕ и СТАРЫЕ изменения (внесённые до сессии или не тобой) в коммит
   НЕ включать. При сомнении по конкретному файлу — спроси пользователя
   отдельно по каждому спорному файлу.

2. **Obsidian-поток** (хранилище `MMLabs_OBSIDIAN/`):
   - создай заметку сессии `MMLabs_OBSIDIAN/sessions/<YYYY-MM-DD>-<тема>.md` —
     что сделано, ключевые файлы/ссылки;
   - обнови `MMLabs_OBSIDIAN/текущие приоритеты.md`;
   - если в сессии принято решение — заметка в `MMLabs_OBSIDIAN/knowledge/decisions/`;
   - если разобран баг — заметка в `MMLabs_OBSIDIAN/knowledge/debugging/`;
   - если появились новые заметки — обнови `MMLabs_OBSIDIAN/00-home/index.md`.

   Созданные/обновлённые заметки сессии тоже входят в список файлов коммита.

3. **Если файлов нет** (ни кода, ни заметок) — коммит НЕ создавать:
   сообщи пользователю «изменений за сессию нет, коммит не нужен» и закончи.

4. **Стейджинг ПОФАЙЛОВО** (D-17) — для каждого файла из списка сессии,
   путь явно и в кавычках (кириллица в путях — норма этого репозитория):

   ```bash
   git add "MM LAB.extension/MM Lab.tab/<...>/script.py"
   git add "MMLabs_OBSIDIAN/sessions/<YYYY-MM-DD>-<тема>.md"
   ```

   `git add .` и `git add -A` ЗАПРЕЩЕНЫ.

5. **Коммит** — сообщение ДОСЛОВНО по шаблону `AGENTS.md` §Git-регламент
   (на русском; каждая сессия — отдельный коммит):

   ```text
   сессия: <краткое описание работы за сессию в одном предложении>

   ## Сессия
   - Агент/модель: <напр. Claude Opus 4.8 / Gemini / Kilo Code>
   - Дата: <YYYY-MM-DD>
   - Изменено файлов: <N>

   ## Изменённые файлы
   - <ТОЛЬКО файлы, затронутые в этой сессии (созданы/изменены)>

   ## Результаты
   - <ключевые изменения списком>
   ```

   «Агент/модель» заполняй фактическим именем агента и модели, под которыми
   работаешь (например «Claude Code / Claude Opus 4.8», «Gemini CLI / Gemini 2.5 Pro»,
   «Kilo Code / <модель>»). Дата — YYYY-MM-DD, N — фактическое число файлов.

6. **Покажи результат** пользователю:

   ```bash
   git -c core.quotepath=false log -1 --stat
   ```

7. **Спроси: «Сделать push?»** Push выполняется ТОЛЬКО после явного «да»
   пользователя (D-18):

   ```bash
   git push
   ```

   Если ответа «да» нет — закончи на локальном коммите, это нормальное
   завершение процедуры.

## Гейты и запреты

- **`git add .` и `git add -A` запрещены** (D-17) — только пофайловый стейджинг
  с явными путями в кавычках.
- **В коммит — только файлы текущей сессии**: чужие/старые изменения не трогать;
  спорные файлы — решением пользователя.
- **Push строго после подтверждения** (D-18): авто-push запрещён; вопрос
  «Сделать push?» задаётся после коммита, и без явного «да» push не выполняется.
- **Шаблон коммита обязателен дословно** — заголовок «сессия: …» и разделы
  «## Сессия», «## Изменённые файлы», «## Результаты»; свои форматы запрещены.
- Кириллические пути: статус и лог — через `git -c core.quotepath=false`.

## Финал

Сообщи пользователю:

- созданные/обновлённые заметки Obsidian (пути);
- хеш и заголовок сессионного коммита + число файлов (из `git log -1 --stat`);
- статус push: выполнен по подтверждению / не выполнялся (коммит локальный);
- если изменений не было — что коммит не создавался и почему.
