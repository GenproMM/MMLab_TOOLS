# /mm-new-button — скаффолд новой кнопки из templates/НоваяКнопка.pushbutton

Создание новой кнопки MM LAB копированием канонического шаблона: копия →
заполнение TODO → регистрация в layout → строгий чекер. Автоматизирует раздел
«Как использовать шаблон» из `templates/НоваяКнопка.pushbutton/README.md`.

## Аргументы

- `<имя кнопки>` — человекочитаемое имя (папка будет `<Имя>.pushbutton`);
- `<панель>` — АРХИТЕКТУРА / ИОС / КООРДИНАЦИЯ.

Если аргументы не заданы — спроси. Панель предлагай с авто-подсказкой,
как в `/mm-adopt-script` (D-10): по назначению будущей кнопки —
Duct/Pipe/Mechanical/MEP/поток/система → ИОС; Room/Area/Wall/Door/Window/IFC/
помещение → АРХИТЕКТУРА; иначе → КООРДИНАЦИЯ. Финальное слово — за человеком.

## Процедура

1. **Согласуй имя и панель** с пользователем (см. Аргументы). Убедись, что папки
   `MM_LAB.extension/MM Lab.tab/<Панель>.panel/<Имя>.pushbutton` ещё нет.

2. **Скопируй шаблон** целиком:
   из `templates/НоваяКнопка.pushbutton/`
   в `MM_LAB.extension/MM Lab.tab/<Панель>.panel/<Имя>.pushbutton/`
   (три файла: `script.py`, `bundle.yaml`, `README.md`). Файлы записывай
   в UTF-8 БЕЗ BOM (MM003).

3. **Заполни все метки `TODO`** (черновой текст согласуй с пользователем):
   - `script.py`: `COMMAND_NAME`, `__title__` (перенос строки через `\n`),
     docstring модуля (название, описание; строки «Совместимость:»
     и «Зависимости:» сохранить), при необходимости `__author__`;
   - `bundle.yaml`: `title` (ru/en_us), `tooltip` (ru/en_us), `author`;
   - `README.md`: разделы «Описание», «Логика работы», «Используемые параметры»
     (или удалить раздел, если параметров нет).
   Канонический lib-бутстрап и транзакционный каркас шаблона НЕ переписывать —
   они и есть конвенция (MM014, D-15).

4. **Зарегистрируй кнопку в layout** (MM007): допиши запись `- <Имя>`
   (имя папки БЕЗ суффикса `.pushbutton`) в `layout:` файла
   `MM_LAB.extension/MM Lab.tab/<Панель>.panel/bundle.yaml`;
   место в списке согласуй или добавь в конец.

5. **Прогони строгий чекер** до зелёного (exit 0):

   ```bash
   py -3 tools/check_convention.py "MM_LAB.extension/MM Lab.tab/<Панель>.panel/<Имя>.pushbutton" --strict
   ```

   Пока exit-код не 0 — исправляй нарушения и повторяй.

6. **Пофайловый коммит по согласованию** с пользователем (D-17): каждый путь
   явно и в кавычках, `git add .`/`-A` запрещены:

   ```bash
   git -c core.quotepath=false status --porcelain
   git add "MM_LAB.extension/MM Lab.tab/<Панель>.panel/<Имя>.pushbutton/script.py"
   git add "MM_LAB.extension/MM Lab.tab/<Панель>.panel/<Имя>.pushbutton/bundle.yaml"
   git add "MM_LAB.extension/MM Lab.tab/<Панель>.panel/<Имя>.pushbutton/README.md"
   git add "MM_LAB.extension/MM Lab.tab/<Панель>.panel/bundle.yaml"
   git commit -m "скаффолд: новая кнопка <Имя> на панели <Панель>"
   ```

   Push — только после явного подтверждения пользователя (D-18).

## Гейты и запреты

- **Запрещено создавать кнопку внутри `templates/`** — шаблон только копируется;
  рабочее место кнопки — исключительно
  `MM_LAB.extension/MM Lab.tab/<Панель>.panel/` (D-14: pyRevit не грузит
  `templates/`, кнопка там никогда не появится).
- **Регистрация в layout обязательна** — кнопка вне `layout:` panel-bundle.yaml
  не видна на pyRevit ≤ 5.x (MM007).
- Панель — выбор человека (D-10); авто-подсказка не заменяет вопрос.
- `git add .` и `git add -A` запрещены (D-17); кириллические пути — в кавычках,
  статус через `git -c core.quotepath=false`.

## Финал

Сообщи пользователю:

- путь созданной кнопки и что она зарегистрирована в layout панели;
- строгий чекер — exit 0;
- напомни положить `icon.png` (PNG, примерно 96×96 px) рядом со `script.py` —
  без него кнопка будет без иконки (это не ошибка);
- напомни сделать pyRevit Reload (или перезапустить Revit) — без этого кнопка
  не появится на панели;
- заготовка — «рабочий пример» (считает стены): логику из TODO-блоков нужно
  дописать под задачу и проверить в Revit (UAT).
