# /mm-adopt-script — приёмка и адаптация стороннего скрипта в кнопку MM LAB

Полный поток приёмки: статическая проверка чекером → выбор панели с авто-подсказкой →
адаптация под конвенцию → РЕВЬЮ-ГЕЙТ (одобрение человека) → регистрация в bundle.yaml →
quick task GSD → пофайловый коммит. Правила конвенции и MM-коды — в `AGENTS.md`
(единственный источник правды); эта процедура ссылается на них по кодам.

## Аргументы

- `<путь>` — путь к стороннему скрипту (`.py`) или папке со скриптом.
  Если аргумент не передан — спроси у пользователя: «Какой скрипт принимаем?
  Дай путь к файлу .py или папке».
- Панель и имя кнопки аргументами НЕ передаются — они согласуются интерактивно
  на шагах 3–4 (решения D-10).

## Процедура

1. **Вход и ограничение безопасности.** Получи путь к стороннему скрипту (`.py`
   или папка). Сторонний скрипт НИКОГДА не исполнять — не запускать ни напрямую,
   ни через `py -3 <скрипт>`, ни импортом: только читать содержимое и анализировать.
   Чекер конвенции статический (`ast.parse`, без import/exec) — это единственный
   допустимый «запуск» анализа.

2. **Исходный отчёт чекера.** Прогони сырой режим и сохрани список нарушений —
   он понадобится для рассказа об адаптационных правках на шаге 7:

   ```bash
   py -3 tools/check_convention.py "<путь>" --json
   ```

   Сырой `.py` проверяется правилами уровня файла (MM000–MM004) и AST-правилами
   (MM008–MM012, MM014); структурные (MM005–MM007, MM013) в этом режиме пропускаются.

3. **Панель (D-10) — вопрос с авто-подсказкой.** Прочитай исходник и предложи
   панель с обоснованием по эвристике содержимого:
   - `Duct` / `Pipe` / `Mechanical` / `MEP` / поток / система → **ИОС**;
   - `Room` / `Area` / `Wall` / `Door` / `Window` / `IFC` / помещение → **АРХИТЕКТУРА**;
   - иначе → **КООРДИНАЦИЯ**.

   Задай пользователю вопрос: «Куда ставим кнопку? Предлагаю **<Панель>**
   (<почему: какие API/термины найдены в скрипте>)» — и ЖДИ ответа.
   Финальное слово — за человеком; его выбор может отличаться от подсказки.

4. **Имя кнопки.** Предложи имя из `__title__` исходника (если есть) или из имени
   файла; согласуй с пользователем. Имя папки кнопки — `<Имя>.pushbutton`.

5. **Адаптация (D-08, D-11).** Подготовь папку
   `MM LAB.extension/MM Lab.tab/<Панель>.panel/<Имя>.pushbutton/` по образцу
   `templates/НоваяКнопка.pushbutton`:
   - `script.py` — перенеси логику исходника, приведя к конвенции:
     - шапка MM001–MM004: строка 1 `#! python3`, строка 2 `# -*- coding: utf-8 -*-`,
       русский docstring со строками «Совместимость: Revit 2020 / 2022 / 2024»
       и «Зависимости:», затем `__title__` и `__author__`;
     - перезапись файла строго UTF-8 БЕЗ BOM (MM003);
     - канонический lib-бутстрап — дословно блок `_SCRIPT_DIR`/`_EXTENSION_DIR`/`_LIB_DIR`
       из шаблона (MM014, D-15);
     - импорты только по белому списку MM008 (stdlib, `clr`/`System`/`Autodesk`/
       `pyrevit`/`Microsoft`, first-party `MM LAB.extension/lib`, vendored
       `openpyxl`/`et_xmlfile`); wildcard-импорты убрать (MM009);
     - `pyrevit.forms` не работает под CPython (MM012) — заменить на `TaskDialog`
       или WinForms-паттерны репозитория;
     - `LookupParameter("строковый литерал")` → `revit_compat.get_parameter(...)`
       с `BuiltInParameter` или `revit_compat.get_shared_parameter(...)` с GUID,
       где применимо (MM010);
     - голые `except:` → `except Exception` (MM011);
     - изменения модели — только в транзакции: `Start()` ПЕРЕД `try`,
       `Commit()` в `try`, `RollBack()` + `raise` в `except`
       (каркас шаблона; правило 10 AGENTS.md);
     - в начале `main()` — `revit_compat.require_supported_version(COMMAND_NAME)` (D-03).
   - `bundle.yaml` — `title` (ru/en_us), `tooltip` (ru/en_us), `author` по формату шаблона.
   - `README.md` — по разделам шаблона (`Описание`, `Логика работы`,
     `Используемые параметры`, `Зависимости`, `Совместимость`).
   - Иконку исходника (`*.png`), если есть, перенеси в папку кнопки как `icon.png`.

6. **Гейт-проверка чекером.** Прогоняй до чистого результата (exit 0):

   ```bash
   py -3 tools/check_convention.py "MM LAB.extension/MM Lab.tab/<Панель>.panel/<Имя>.pushbutton" --strict
   ```

   В `--strict` baseline игнорируется, warning считаются error (гейт приёмки D-06/D-08).
   Пока exit-код не 0 — исправляй и повторяй.

7. **РЕВЬЮ-ГЕЙТ (D-08, блокирующий).** Покажи пользователю:
   - (а) сводку адаптационных правок по пунктам: что и почему изменено,
     с отсылкой к MM-кодам из отчёта шага 2 (например: «убран
     `from Autodesk.Revit.DB import *` — MM009», «`pyrevit.forms` заменён
     на `TaskDialog` — MM012»);
   - (б) полный diff относительно исходника и/или полное содержимое новых файлов
     (`script.py`, `bundle.yaml`, `README.md`).

   ЖДИ явного одобрения («да» / «одобряю»). Без одобрения — СТОП: ничего
   не регистрировать (шаг 8 не выполняется), quick task не заводить, коммит
   не делать; созданные файлы удалить по желанию пользователя.

8. **Регистрация (D-11).** Только после одобрения на шаге 7:
   - допиши запись `- <Имя>` (имя папки БЕЗ суффикса `.pushbutton`) в `layout:`
     файла `MM LAB.extension/MM Lab.tab/<Панель>.panel/bundle.yaml`;
     место в списке согласуй с пользователем или добавь в конец;
   - если исходный скрипт уже лежал кнопкой в этом репозитории и его запись есть
     в `tools/convention_baseline.json` (ключ `units`) — удали эту запись:
     дальше кнопка держит `--strict` без поблажек;
   - контрольный прогон всего репозитория — должен вернуть exit 0:

   ```bash
   py -3 tools/check_convention.py --all --baseline tools/convention_baseline.json
   ```

9. **Quick task GSD (D-09).** Зафиксируй приёмку как quick task:
   - **Claude Code:** вызови `/gsd-quick` с описанием приёмки
     («приёмка: кнопка <Имя> адаптирована под конвенцию MM LAB, панель <Панель>»).
   - **Gemini CLI / Kilo Code** (GSD-команд нет) — создай артефакты вручную
     по живому образцу `.planning/quick/260709-jko-get-parameter-typeerror-builtinparameter/`:
     - папка `.planning/quick/<YYMMDD-xxx>-adopt-<слаг-кнопки>/`,
       где `<YYMMDD-xxx>` — id вида `260724-abc` (дата + 3 латинские буквы);
     - файл `<id>-PLAN.md` — frontmatter `quick_id: <id>` и `status: complete`,
       разделы `## Task` (что принимали, откуда) и `## Adaptation summary`
       (список правок с MM-кодами);
     - файл `<id>-SUMMARY.md` — краткий итог приёмки и список затронутых файлов;
     - строка в таблицу «Quick Tasks Completed» в `.planning/STATE.md`.

10. **Коммит (D-17).** Стейджинг ПОФАЙЛОВЫЙ — только созданные/изменённые файлы,
    каждый путь явно и в кавычках (кириллица!); `git add .` и `git add -A` запрещены:

    ```bash
    git -c core.quotepath=false status --porcelain
    git add "MM LAB.extension/MM Lab.tab/<Панель>.panel/<Имя>.pushbutton/script.py"
    git add "MM LAB.extension/MM Lab.tab/<Панель>.panel/<Имя>.pushbutton/bundle.yaml"
    git add "MM LAB.extension/MM Lab.tab/<Панель>.panel/<Имя>.pushbutton/README.md"
    git add "MM LAB.extension/MM Lab.tab/<Панель>.panel/bundle.yaml"
    git add "tools/convention_baseline.json"
    git commit -m "приёмка: кнопка <Имя> адаптирована под конвенцию MM LAB"
    ```

    (Списки файлов подстрой под фактический состав: icon.png, артефакты quick task
    в `.planning/quick/` и т.п.) Push НЕ делать без явного подтверждения
    пользователя (D-18).

11. **Финал.** Напомни пользователю: сделать pyRevit Reload (или перезапустить
    Revit) — расширение парсится на старте, без Reload кнопка не появится;
    затем проверить кнопку на панели `<Панель>` в реальном Revit (чекер
    статический, runtime-истина — только UAT). Если сессия завершается —
    предложи `/mm-save-session`.

## Гейты и запреты

- **Не исполнять сторонний код** — принимаемый скрипт запрещено запускать,
  импортировать или выполнять любым способом до одобрения и вне Revit;
  анализ только чтением и статическим чекером. Запуск адаптированной кнопки —
  человеком в Revit после ревью.
- **Регистрация только после одобрения** — шаг 8 (bundle.yaml, baseline)
  и последующие выполняются строго после явного «да» на РЕВЬЮ-ГЕЙТЕ (шаг 7).
  Никаких тихих изменений (D-08).
- **`git add .` и `git add -A` запрещены** (D-17) — только пофайловый стейджинг
  с явными путями в кавычках.
- **Push без подтверждения запрещён** (D-18).
- **Кириллические пути в git** — все git-команды со статусом/путями выполняй
  через `git -c core.quotepath=false`, пути всегда в кавычках.

## Финал

Сообщи пользователю:

- кнопка `<Имя>` создана в панели `<Панель>` и зарегистрирована в layout;
- какие правки внесены при адаптации (короткая сводка с MM-кодами);
- строгий чекер (`--strict`) и общий прогон с baseline — exit 0;
- quick task заведён (id и путь в `.planning/quick/`);
- коммит создан (хеш), push не выполнялся (или выполнен — если пользователь подтвердил);
- следующий шаг за человеком: pyRevit Reload и проверка кнопки в Revit.
