# /mm-check — проверка кнопки/скрипта/репозитория на соответствие конвенции MM LAB

Прогон машинного гейта `tools/check_convention.py` с пересказом результата по-русски.
Коды правил MM000–MM014 и их смысл — в `AGENTS.md` §Проверка конвенции.

## Аргументы

- `<путь>` (один или несколько) — папка кнопки `*.pushbutton` или одиночный `.py`
  (режим «сырого скрипта»: структурные правила MM005–MM007, MM013 пропускаются);
- `--all` — весь репозиторий (все кнопки `MM_LAB.extension/MM Lab.tab/**/*.pushbutton`
  плюс проверка орфанов layout);
- `--strict` — гейт приёмки: baseline игнорируется, warning считаются error.

Если аргументы не переданы — спроси пользователя: «Что проверяем: конкретную
кнопку/скрипт (дай путь) или весь репозиторий (`--all`)?»

## Процедура

1. **Выбери команду** по цели проверки:

   ```bash
   # одна кнопка или сырой .py
   py -3 tools/check_convention.py "<путь>"

   # весь репозиторий — ВСЕГДА с baseline легаси-кнопок
   py -3 tools/check_convention.py --all --baseline tools/convention_baseline.json

   # новая/адаптируемая кнопка — гейт приёмки
   py -3 tools/check_convention.py "<путь>" --strict
   ```

   Для машинного разбора результата добавь флаг `--json` (ровно один JSON-объект
   в stdout).

2. **Выполни команду** и зафиксируй exit-код.

3. **Трактовка exit-кодов:**
   - `0` — чисто: нарушений нет (или все покрыты baseline);
   - `1` — есть нарушения уровня error (в `--strict` — и warning);
   - `2` — ошибка использования или внутренняя ошибка чекера (неверный путь,
     битые аргументы) — разбери сообщение и поправь вызов.

4. **Перескажи результат по-русски:** сгруппируй нарушения по кнопкам, внутри
   кнопки — по MM-кодам; для каждого кода дай краткое пояснение (расшифровка
   кодов — таблица в `AGENTS.md` §Проверка конвенции).

5. **При нарушениях — предложи исправления** по каждому коду со ссылкой на
   соответствующее правило `AGENTS.md` (например: MM009 → «замени
   `from X import *` на явные импорты», MM010 → «используй
   `revit_compat.get_parameter`»). НИЧЕГО не правь без явного запроса
   пользователя — команда только проверяет и советует.

## Гейты и запреты

- Процедура read-only: чекер не исполняет проверяемый код (только чтение
  и `ast.parse`), и сама команда не вносит правок — исправления только
  по отдельному запросу пользователя.
- Для новых и адаптируемых кнопок единственный валидный гейт — `--strict`:
  baseline покрывает только замороженные нарушения legacy-кнопок.
- Прогон `--all` без `--baseline tools/convention_baseline.json` даст ложный
  «красный» результат по легаси-кнопкам — не пугать им пользователя.

## Финал

Сообщи пользователю:

- какая команда выполнялась и итоговый exit-код с трактовкой;
- список нарушений по кнопкам и MM-кодам (или «чисто — нарушений нет»);
- предложенные исправления по каждому коду (если нарушения есть) и напоминание,
  что правки выполняются отдельным решением пользователя (например, через
  `/mm-adopt-script` для полноценной адаптации).
